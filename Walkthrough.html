Methadata — Walkthrough

Jak uruchomić aplikację oraz jak przebiega szukanie, kategoryzowanie i grupowanie materiałów reklamowych.

Co robi system: Methadata łączy materiały reklamowe i strony docelowe (zapisy stron, HAR, zrzuty ekranu, PDF, wideo, audio, adresy URL) w wyjaśnialne grupy kampanii. Każde połączenie ma uzasadnienie: wynik na rodzinę cech, wspólne ślady i możliwość sprawdzenia, co się stanie po wyłączeniu rodziny.

Uruchomienie (Docker)

Jedyny wymagany składnik to Docker z Compose v2. Nie trzeba pliku .env, prywatnego korpusu ani ręcznego importu — backend sam zasiewa syntetyczną próbkę demonstracyjną.

docker compose up --build      # start (pierwsze budowanie pobiera obrazy i zależności)
docker compose logs -f         # logi obu usług (logs -f backend, logs -f frontend)
docker compose down            # stop (dane zostają w wolumenie methadata-data)
docker compose down -v         # stop i usunięcie danych

Pierwszy przebieg

  1. Otwórz http://localhost:5173 — ekran Nowa analiza.
  2. Kliknij Uruchom przykład. Profil demo używa syntetycznej próbki: materiały A i C to warianty jednej kampanii i tworzą grupę, B (inny temat i szablon) zostaje osobno.
  3. W wyniku otwórz Pokaż dowody dla pary z grupy — zobaczysz grafiki z obu stron, wynik na rodzinę cech i uzasadnienie.
  4. Przejdź do Baza materiałów (/collection) i dodaj własny plik lub ZIP przyciskiem Dodaj do bazy.
  5. Raport importu powie, czy materiał dołączył do istniejącej grupy, utworzył nową grupę (potencjalna nowa kampania), czy został bez grupy.
Stan widoku żyje w adresie. /runs/:id, /collection/{graph|evidence|timeline|files} oraz filtry (?q=, ?domain=, ?period=, ?min=, ?group=, ?material=, ?evidence=) są w URL-u, więc „wstecz”, odświeżenie i udostępnienie linku odtwarzają dokładnie ten sam widok.

Warianty uruchomienia

Tryb pełny (modele ML, wideo i audio)

Domyślny obraz jest lekki: bez modeli ML i bez ffmpeg. Grafiki, tekst, struktura stron, HAR i PDF działają od razu, a wideo/audio i embeddingi są pomijane z jawnym oznaczeniem „brak”. Pełny zestaw:

METHADATA_EXTRAS='web,media,pdf,ocr,perceptual,semantic,speech,visual-embedding' \
METHADATA_WITH_FFMPEG=1 METHADATA_COLLECTION_MODELS=1 docker compose up --build

Wagi modeli pobierają się przy pierwszym użyciu (kilkaset MB) i wymagają dostępu do sieci.

Profil jury (lokalny korpus zapisów stron)

pip install -e '.[web,media,pdf]'
python -m methadata_api.prepare_jury --data-dir var/jury
docker compose -p methadata-jury -f compose.yaml -f configs/demo/compose.jury.yaml up --build -d --wait

Przygotowanie tworzy indeks i magazyn w var/jury oraz pakiet var/jury/p15.zip (HTML, zasoby strony, HAR, zrzut ekranu) do wgrania na ekranie analizy. Nakładka Compose ustawia METHADATA_ANALYSIS_PROFILE=jury i wskazuje przygotowany magazyn przez METHADATA_JURY_DATA_DIR.

Rozwój bez Dockera

# backend (port 8000)
pip install -e '.[web,media,pdf]'
METHADATA_DATA_DIR=var/methadata-data python -m methadata_api

# frontend (port 5173, proxy na http://localhost:8000)
cd frontend && npm ci && npm run dev

# testy
pip install -e '.[test,media,pdf,ocr,web]' && pytest
python contracts/http/check_conformance.py --base-url http://localhost:8000

Brak danych nie zatrzymuje analizy. Materiał z samym adresem albo bez części modalności jest porównywany tylko tam, gdzie są dane; interfejs pokazuje „Za mało danych” zamiast zgadywać wynik.

Szukanie

Pole Szukaj w bazie materiałów (parametr ?q=) filtruje lokalnie, bez zapytań do sieci. Jedna fraza — porównywana małymi literami w regułach pl-PL — jest dopasowywana do czterech rzeczy:

Treść materiału

Indeks search_text: zlepek cech lexical/text_field (tytuły i akapity, do 1500 znaków na materiał), budowany przy publikacji migawki grafu.

Nazwa i adres

material_id, etykieta materiału oraz display_url.

Domeny

Wszystkie hosty wykryte w materiale (HTML, HAR, łańcuchy przekierowań).

Wspólne ślady

Etykiety śladów (wspólna grafika, domena, tracker, skrypt, kod afiliacyjny…). Trafienie w ślad wybiera wszystkie materiały, które go mają.

Fraza zawęża jednocześnie listę materiałów, graf i listę grup: grupa pokazuje tylko tych członków, którzy przeszli filtr, a grupy bez trafień znikają z listy. Przycisk Eksport JSON zapisuje aktualny wycinek wraz z użytymi filtrami (query, domain, period_days, minimum_score).

Z ekranu analizy

Kafelek Wskazówka („np. nazwa preparatu lub nazwisko”) przenosi frazę do bazy jako /collection?q=…. To ta sama ścieżka co pole Szukaj — nie uruchamia nowego przebiegu analizy.

Ślady wspólne (graf artefaktów)

Wzbogacenie domen

DNS / TLS / RDAP dokładają kategorie techniczne: adres IP hostingu, wystawca certyfikatu, rejestrator i wiek domeny — przydatne przy odróżnianiu wspólnej infrastruktury od wspólnej treści.

Grupowanie (fuzja)

Grupy powstają z par, nie z globalnego podobieństwa. Dla każdej pary materiałów fuzja (fusion-v1) liczy trzy rozdzielone wielkości:

Podobieństwo

Ważona średnia wyników dostępnych źródeł treści.

Pokrycie

Udział wagi źródeł, które dały wynik: Σw dostępnych / Σw skonfigurowanych.

Wsparcie

Liczba odrębnych źródeł treści z wynikiem ≥ support_min.

Krawędź powstaje tylko wtedy, gdy spełnione są wszystkie trzy warunki:

pokrycie >= coverage_min   AND   wsparcie >= min_support   AND   fuzja >= threshold
  • Brak pokrycia → score = None, czyli „porównanie niewykonalne” (status insufficient_coverage lub no_evidence).
  • Brak wsparcia → wynik obcięty tuż poniżej progu i oznaczony w wyjaśnieniu, więc klastrowanie nie połączy pary (insufficient_support).
  • Rodziny o tym samym origin (np. OCR akapitu i ten sam tekst z HTML) to jedno źródło treści — wkład liczy się raz i nie podbija ani pokrycia, ani wsparcia.

Profile grupowania

Wagi i progi są parametrami konfiguracji (configs/fusion/eval.json), nie wartościami dopasowanymi do danych: równe wagi, support_min = threshold.

Profil kampania: threshold = 0,5, coverage_min = 0,5, równe wagi 1,0 dla assets-jaccard-v1 (grafiki), lexical-tfidf-v1 (tekst) i dom-paths-jaccard-v1 (struktura HTML); krawędź wymaga wsparcia dwóch niezależnych rodzin. Ustalenie wspólnego nadawcy wymaga osobnych dowodów.

Od krawędzi do grupy

Krawędzie, które przeszły bramki, trafiają do klastrowania przez spójne składowe (components-threshold-v1). W repozytorium są też alternatywy: Leiden, gęstościowe, spektralne, medoidy, konsensus, nakładające się, miękkie przypisania, bikastrowanie, przyrostowe i ograniczone (constrained).

Sugestie przerywane: pary, które minęły próg o włos lub oparły się na jednej rodzinie, nie są scalane, ale pokazują się jako sugerowane krawędzie (do 40 najlepszych) wraz z wyjaśnieniem — analityk może je potwierdzić ręcznie.

Dowody i co-jeśli

  1. Pokaż dowody otwiera /collection/evidence?evidence=… albo /runs/:id/evidence/:id — zawsze adresowalny link.
  2. Panel pokazuje wynik na rodzinę cech, podglądy obu stron i odnośniki Locator: text_span (zakres znaków), image_rect (prostokąt w obrazie lub klatce), har_entry (wpis logu), byte_range (fragment MHTML).
  3. Scenariusze co-jeśli (/api/v1/runs/{id}/evidence/{id}/scenarios) przeliczają parę z wyłączoną rodziną cech — widać, czy połączenie trzyma się na grafikach, tekście czy szablonie.
  4. Skanuj źródło (widok Pliki źródłowe) wykonuje jeden przebieg monitora nad eksportem JSON/JSONL i pokazuje, ile reklam jest nowych lub zmienionych od poprzedniego skanu oraz ile grup płatników ma nowe wpisy. Nowe rekordy idą do osobnego magazynu i nie zmieniają grafu kolekcji.

Podsumowanie grupy jest domyślnie deterministyczne i liczone bez sieci: liczba materiałów, wspólne rodziny śladów i najwyższe podobieństwo.

Dane wychodzące

Analiza działa lokalnie. Tylko trzy funkcje kontaktują się z zewnętrznymi usługami i każdą da się wyłączyć.

FunkcjaCo opuszcza komputerStan domyślny i wyłączenie
Podsumowania grup (OpenAI)zwarty opis grupy: tytuły i fragmenty tekstu (do 220 znaków), domeny, trackery, liczby i wynikiwyłączone włącza METHADATA_ENABLE_LLM=1 razem z OPENAI_API_KEY; METHADATA_DISABLE_LLM=1 wyłącza także przy ustawionym ENABLE
Wzbogacanie domen (DNS, TLS, RDAP)zapytania do publicznych nazw hostów z materiałów; połączenie TLS ujawnia adres IP analitykawłączone; METHADATA_DISABLE_ENRICHMENT=1
Pobranie strony z adresu URLzapytanie HTTP do podanego adresu (bezpieczny fetch, bez adresów prywatnych)włączone; odznacz „Pobierz stronę”
Materiały objęte zakazem rozpowszechniania: pracuj z METHADATA_DISABLE_LLM=1 i METHADATA_DISABLE_ENRICHMENT=1. Podsumowania LLM są wyłączone domyślnie, więc bez świadomego włączenia żaden fragment materiałów nie opuszcza komputera.

Wzbogacanie nie odpytuje adresów prywatnych, loopback ani link-local, więc spreparowany HAR nie posłuży do skanowania sieci wewnętrznej. Testy automatyczne mają obie usługi wyłączone na stałe (tests/conftest.py).
