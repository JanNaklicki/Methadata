Methadata — Walkthrough

Od uruchomienia aplikacji do gotowego grafu kampanii: jeden ciągły proces łączenia, wyjaśniania i śledzenia ewolucji fałszywych reklam.

Co robi system: Methadata zamienia luźny zbiór podejrzanych materiałów (zapisy stron HTML/MHTML, HAR, zrzuty ekranu, PDF, wideo, audio, adresy URL) w wyjaśnialne grupy kampanii. Każde połączenie ma dowody na poziomie cech, ocenę kosztu mutacji (PhyloFake v1) i symulację co-jeśli.

Uruchomienie (Docker)

Jedyny wymagany składnik to Docker z Compose v2. Nie trzeba pliku .env, klucza API ani konfiguracji wstępnej — po starcie od razu wrzucasz własne materiały.

docker compose up --build      # start (pierwsze budowanie pobiera obrazy i zależności)
docker compose logs -f         # logi obu usług (logs -f backend, logs -f frontend)
docker compose down            # stop (dane zostają w wolumenie methadata-data)
docker compose down -v         # stop i usunięcie danych

Interfejs

http://localhost:5173

żądania /api i /static idą przez proxy Vite do backend:8000

API

http://localhost:8000 (tylko localhost)

health: /api/v1/health

Dane

Wolumen methadata-data

magazyn i przebiegi przeżywają down i restart

Pierwszy import (własny ZIP)

Podstawowa ścieżka pracy to Baza materiałów (/collection): zaczyna pusta i zawiera wyłącznie to, co sam zaimportujesz. Graf, grupy, PhyloFake i dowody liczą się nad Twoimi materiałami.

  1. Otwórz http://localhost:5173/collection (albo wybierz Baza materiałów w nawigacji).
  2. Kliknij Dodaj do bazy i wskaż własny ZIP z zapisami stron — jeden plik, wiele plików, archiwum zagnieżdżone albo adres URL/domenę. Przyjmowane są też pojedyncze HTML/MHTML, HAR, zrzuty ekranu, PDF, wideo i audio.
  3. Otworzy się raport importu z postępem i statusem każdego wpisu: co zostało dodane, co pominięte, co rozpoznane jako duplikat.
  4. Raport od razu mówi, co stało się z każdym materiałem: dołączył do istniejącej grupy, utworzył nową grupę, czy został bez grupy.
  5. Przejdź do widoku graph — węzły ze złotym pierścieniem ★ to szablony źródłowe (Patient Zero), etykiety krawędzi pokazują wynik i typ mutacji (np. KLON, SWAP OSOBY, INFRA). Kliknij krawędź i otwórz Pokaż dowody.
Baza materiałów vs. jednorazowa analiza. Ekran Nowa analiza porównuje wgrany plik z indeksem profilu analizy, w którym backend może trzymać próbkę startową. Jeśli chcesz pracować wyłącznie na swoich plikach, importuj przez Baza materiałów.
Stan widoku żyje w adresie URL. /collection/{explorer|graph|evidence|timeline|files} oraz filtry (?q=, ?domain=, ?period=, ?min=, ?group=, ?material=, ?evidence=) są w adresie — „wstecz”, odświeżenie i wysłanie linku odtwarzają dokładnie ten sam widok.

Warianty uruchomienia

Tryb pełny (modele ML, wideo i audio)

Domyślny obraz jest lekki (bez wag ML i bez ffmpeg). Grafiki, tekst, struktura HTML, HAR, PDF i PhyloFake działają od razu, a wideo/audio i embeddingi są pomijane z jawnym oznaczeniem „brak”. Pełny zestaw:

METHADATA_EXTRAS='web,media,pdf,ocr,perceptual,semantic,speech,visual-embedding' \
METHADATA_WITH_FFMPEG=1 METHADATA_COLLECTION_MODELS=1 docker compose up --build

Wagi modeli (RapidOCR, MiniLM, OpenCLIP, Faster-Whisper, SpeechBrain) pobierają się przy pierwszym użyciu (kilkaset MB) i są cache'owane lokalnie.

Czysta baza

docker compose down -v        # usuwa wolumen methadata-data
docker compose up --build

Pojedyncze materiały można też archiwizować i przywracać w widoku Pliki źródłowe bez czyszczenia całości.

Rozwój bez Dockera

# backend (port 8000)
pip install -e '.[web,media,pdf]'
METHADATA_DATA_DIR=var/methadata-data python -m methadata_api

# frontend (port 5173, proxy na http://localhost:8000)
cd frontend && npm ci && npm run dev

# testy
pip install -e '.[test,media,pdf,ocr,web]' && pytest
python contracts/http/check_conformance.py --base-url http://localhost:8000

Jeden proces: od pliku do mapy kampanii

Wszystko, co robi Methadata — od wgrania pliku, przez szukanie i grupowanie, aż po wskazanie szablonu źródłowego i badanie dowodów — układa się w 6 kolejnych kroków jednego potoku. Kliknij dowolny etap, żeby przejść do szczegółów:

01

Import, rozpoznanie formatu i deduplikacja

src/methadata/ingest/ · collection_archive.py

System przyjmuje dowolny materiał z dochodzenia — pojedynczy plik, archiwum ZIP z wieloma zapisami stron albo sam adres URL — i zamienia go na spójny rekord w magazynie.

Wejście: ZIP / HTML / MHTML / HAR / PNG / PDF / MP4 / MP3 / URL → Wynik: niezmienny blob SHA-256 + deterministyczny canonical_id
Rodzaj wejściaJak działaCo się dzieje przy problemach
Import do bazy (ZIP / pliki) podstawowyRozpakowanie do 3 poziomów zagnieżdżenia (do 5 000 wpisów, 128 MiB na plik), automatyczne rozpoznanie typu (sniff).Ponowny import tego samego zapisu daje identyczny canonical_id → oznaczany jako duplikat, nie tworzy drugiego węzła.
Adres URL lub domenaPrzyjmuje pełny URL, samą domenę oraz długie linki reklamowe z trackerami (wyciąga też zagnieżdżony docelowy URL); bezpieczny fetch z zapisem przekierowań (SSRF-safe).Gdy strona nie odpowiada, zapisuje się sam adres i domena — analiza nie przerywa się, a materiał dostaje oznaczenie niepełnych danych.
Wskazówka tekstowaNazwa preparatu, nazwisko, domena wpisane na ekranie startowym.Otwiera /collection?q=… (filtrowanie lokalne bez uruchamiania nowego przebiegu).
02

Ekstrakcja cech, śladów i wzbogacenie domen

src/methadata/extractors/ · experiments/ · enrichment.py

Każdy materiał jest rozkładany na niezależne Feature z odnośnikami do miejsca w pliku (evidence_refs). Brak którejś modalności (np. sam screenshot bez HTML) nigdy nie zatrzymuje potoku.

Wejście: rekord materiału z kroku 01 → Wynik: 3 rodziny bazowe + kilkanaście sygnałów technicznych i medialnych

3 rodziny bazowe (decydują o grupach)

  • Grafiki (assets-jaccard-v1) — hashe SHA-256 obrazów ze strony i zrzutów.
  • Tekst (lexical-tfidf-v1) — znormalizowane tytuły i akapity (TF-IDF).
  • Struktura HTML (dom-paths-jaccard-v1) — szkielet ścieżek znaczników DOM (wykrywa ten sam szablon nawet po podmianie treści).

Sygnały dodatkowe i wzbogacenie (widoczne w śladach i PhyloFake)

  • Infrastruktura i kod: domeny, łańcuchy przekierowań HAR, piksele i trackery (np. meta_pixel), identyczne skrypty JS, DNS / TLS / RDAP (IP, rejestrator, wiek domeny, certyfikat).
  • Media i tożsamość: pHash, OCR (RapidOCR), semantyka tekstu (MiniLM), podobieństwo wizualne (OpenCLIP), dopasowanie do bazy osób referencyjnych (var/reference_figures), mowa i głos (Whisper + SpeechBrain).
  • Ślady finansowe i kontaktowe: kody afiliacyjne, QR, zanonimizowane telefony/e-maile (HMAC).
03

Porównanie par i Fuzja (fusion-v1)

clustering/fusion/core.py · configs/fusion/eval.json

Materiały porównuje się parami. Zamiast jednej „czarnej skrzynki”, fuzja rozdziela ocenę na trzy proste, sprawdzalne bramki — krawędź powstaje dopiero, gdy przejdą wszystkie trzy:

1. Pokrycie
pokrycie ≥ 0,50
Czy obie strony miały dość porównywalnych danych? Jeśli nie → Za mało danych (bez zgadywania).
AND
2. Wsparcie
wsparcie ≥ 2 rodziny
Czy zgodność potwierdzają co najmniej dwa niezależne źródła (np. szablon DOM + grafiki)?
AND
3. Podobieństwo
wynik fuzji ≥ 0,50
Ważona średnia wyników dostępnych rodzin (domyślny profil kampania: równe wagi 1,0).

Brak podwójnego liczenia

Rodziny pochodzące z tego samego źródła (origin, np. ten sam akapit z HTML i z OCR zrzutu) liczą się raz — nie zawyżają ani pokrycia, ani wsparcia.

Sugestie przerywane (do weryfikacji ręcznej)

Pary, które minęły próg o włos lub oparły się na jednej rodzinie (np. tylko wspólny tracker), nie scalają się automatycznie — pojawiają się na grafie jako przerywane bursztynowe krawędzie, które analityk może jednym kliknięciem potwierdzić albo odrzucić.

04

Klastrowanie w grupy kampanii i nadanie kategorii

clustering/components/ · leiden/ · density/

Krawędzie, które przeszły wszystkie trzy bramki z kroku 03, trafiają do algorytmu spójnych składowych (components-threshold-v1), tworząc czytelne grupy kampanii (w repozytorium dostępne są też Leiden, gęstościowe, spektralne i konsensus).

Wejście: zaakceptowane krawędzie PairEvidence → Wynik: grupy kampanii + status każdego materiału + typ relacji

Status materiału

grouped singleton noise insufficient_data

Materiał bez mocnych powiązań zostaje osobno (singleton) albo z ostrzeżeniem o braku danych — system nigdy nie wrzuca go na siłę do losowej grupy.

Rodzaj relacji na parze

shared_template shared_narrative campaign_candidate

Mówi od razu, co połączyło parę: wspólny szablon strony, wspólna historia/tekst, czy komplet sygnałów kampanii.

05

PhyloFake v1 — ewolucja kampanii, Slot-Swap i Patient Zero

src/methadata/phylofake/engine.py

Zwykłe klastrowanie mówi tylko, że materiały są podobne. PhyloFake v1 idzie o krok dalej: waży ślady według kosztu ich zmiany po stronie oszusta, rozpoznaje konkretny rodzaj przeróbki reklamy, wskazuje źródło kampanii i znajduje ukryte mosty między osobnymi grupami.

Wejście: grupy z kroku 04 + wszystkie ślady z kroku 02 → Wynik: waga ACIG · etykieta mutacji · ★ Patient Zero · 2-skokowe mosty operatora

1. Koszt zmiany po stronie oszusta (ACIG)

Każdy wspólny ślad dostaje wagę: (log((N+1)/(df+1)) + 0,15) × C_mutate. Zmiana domeny (0,7×) czy nagłówka (0,8×) kosztuje oszusta sekundy, ale podmiana piksela reklamowego (3,0×), głosu lektora (2,6×), skryptu JS (2,5×) czy serwera (2,2×) jest kosztowna — dlatego to one ważą najwięcej.

2. Szablon źródłowy (★ Patient Zero)

W każdej grupie PhyloFake wybiera węzeł źródłowy (najwcześniejszy znacznik czasu, centralność i liczba wspólnych śladów) oraz buduje drzewo ewolucji maksymalnego ACIG. Na grafie wyróżnia go złoty pierścień i gwiazdka ★.

3. Klasyfikacja mutacji (Slot-Swap)

KLON · CLONE
Bezpośrednia kopia tej samej kampanii (zwykle rotacja domeny po blokadzie).
SWAP OSOBY · CELEBRITY_SWAP
Ten sam szablon i zaplecze, podmieniona osoba publiczna — np. Krzysztof Stanowski ↔ Tomasz Sekielski (p3 ↔ p4).
SWAP PRODUKTU · PRODUCT_SWAP
Ten sam szablon i haczyk, podmieniona nazwa rzekomego preparatu lub platformy.
CROSS-MEDIA
Wspólny głos, twarz lub narracja między różnymi formatami (np. wideo i landing page).
INFRA · INFRA_REUSE
Różne kreacje, ale ten sam meta_pixel, skrypt JS albo serwer jednego operatora.
WARIANT · TEMPLATE_VARIANT
Modyfikacja tego samego szablonu kampanii (test A/B nagłówka lub układu).

4. Dwuskokowe mosty hipergrafowe (ukryte powiązania między grupami)

Nawet gdy dwie kampanie wyglądają zupełnie inaczej, PhyloFake wykrywa 2-skokowe ścieżki przez wspólne ślady wysokiego kosztu — np. łącząc kampanię z wizerunkiem Rafała Brzoski (p1/p2) z kampanią z Krzysztofem Stanowskim (p3) przez ten sam Meta Pixel:

p2 ──[script: 51eb40e5…]──▶ ★ p1 ──[tracker: meta_pixel · 4567646436826205]──▶ ★ p3
06

Eksploracja, szukanie, dowody i scenariusze co-jeśli

frontend/src/components/ · /api/v1/collection · /scenarios

Na końcu analityk pracuje na interaktywnym widoku bazy materiałów — filtruje, sprawdza podglądy dowodów, testuje odporność powiązań i eksportuje wyniki.

explorer — grupy, ★ źródła i ślady graph — graf powiązań i artefaktów evidence — dowody pary i co-jeśli timeline — oś czasu files — pliki źródłowe i monitor

Szukanie (?q=) i filtry

Lokalne wyszukiwanie (reguły pl-PL) dopasowuje jednocześnie treść materiału (search_text), nazwę i URL, domeny oraz etykiety wspólnych śladów. Filtry domain, period (7/30 dni), min (≥65% / ≥85%) i group zawężają naraz graf, listę grup i Eksport JSON.

Graf powiązań vs. Graf śladów

Domyślny graf WebGL (Sigma.js 4) pokazuje materiały, ★ Patient Zero, etykiety mutacji i przerywane sugestie. Przełącznik ?graph=artifacts przestawia graf na układ dwudzielny wokół wspólnego obiektu (grafika z podglądem, domena, piksel, skrypt).

Dowody z Locatorami i „Co-jeśli”

Panel dowodów pokazuje wynik na rodzinę, boks PhyloFake (ACIG + ślady), podglądy stron i precyzyjne wskaźniki (text_span, image_rect, har_entry, byte_range). Scenariusze co-jeśli przeliczają parę z wyłączoną rodziną cech — od razu widać, na czym trzyma się połączenie.

Skanuj źródło (Monitor reklam)

Przycisk w bazie uruchamia przebieg methadata.monitor nad źródłem JSON/JSONL (lub Meta Ad Library API) i raportuje nowe/zmienione reklamy oraz płatników w osobnym magazynie, bez naruszania bieżącego grafu.

Determinizm całego procesu: run_experiment() wylicza run_id jako SHA-256 z konfiguracji, dataset_version i posortowanych canonical_id. Ten sam wsad + ta sama konfiguracja = identyczny wynik po każdym restarcie.

Dane wychodzące

Analiza działa lokalnie. Tylko trzy funkcje kontaktują się z zewnętrznymi usługami i każdą da się wyłączyć.

FunkcjaCo opuszcza komputerStan domyślny i wyłączenie
Podsumowania grup (OpenAI)zwarty opis grupy: tytuły i fragmenty tekstu (do 220 znaków), domeny, trackery, liczby i wynikiwyłączone włącza METHADATA_ENABLE_LLM=1 razem z OPENAI_API_KEY; METHADATA_DISABLE_LLM=1 wyłącza bezwarunkowo
Wzbogacanie domen (DNS, TLS, RDAP)zapytania do publicznych nazw hostów z materiałów; połączenie TLS ujawnia adres IP analitykawłączone; METHADATA_DISABLE_ENRICHMENT=1
Pobranie strony z adresu URLzapytanie HTTP do podanego adresu (bezpieczny fetch, bez adresów prywatnych)włączone; odznacz „Pobierz stronę”
Materiały objęte zakazem rozpowszechniania: pracuj z METHADATA_DISABLE_LLM=1 i METHADATA_DISABLE_ENRICHMENT=1. Podsumowania LLM są wyłączone domyślnie, więc bez świadomego włączenia żaden fragment materiałów nie opuszcza komputera.

Wzbogacanie nie odpytuje adresów prywatnych, loopback ani link-local, więc spreparowany HAR nie posłuży do skanowania sieci wewnętrznej. Testy automatyczne mają obie usługi wyłączone na stałe (tests/conftest.py).
