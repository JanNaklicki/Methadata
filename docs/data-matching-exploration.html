Methadata — Data Matching & Exploration

Internal reference for the analysis pipeline, data contracts, extraction methods, and HTTP API.

Purpose: Methadata detects whether a set of advertising materials (web pages, images, HAR archives, ZIP captures) share a common origin — same template, same campaign, or same creator. It does this by extracting multi-modal signals from each material and fusing the per-pair evidence into clusters.

Core Data Model

All records are Pydantic v2 models in src/methadata/contracts/models.py. Schema version is "1".

Observation

A single captured material. Contains one or more Artifacts. Identified by:

  • observation_id — unique import ID
  • canonical_id — content-based identity (deduplication key)
  • input_kind — full_capture | url_only | creative_only
  • source_ref — original path / URL

Artifact

A file within an Observation. Roles:

  • landing_html / landing_dom — page source / rendered DOM
  • landing_screenshot — screenshot PNG
  • creative_image — ad image
  • resource — network resource (images, scripts…)
  • har — HTTP Archive
  • video / audio / document / archive / other

Feature

An extracted signal from one Observation. Fields: family, kind, value_type, value, evidence_refs (ArtifactRef list).

Examples: asset/image_sha256, lexical/text_field, dom_struct/dom_sequence, perceptual/phash.

PairEvidence

A similarity score between exactly two materials (by canonical_id). Fields:

  • pair — sorted tuple of two canonical_ids
  • method_id — which comparator produced it
  • relation — shared_template | shared_narrative | campaign_candidate
  • score — 0–1 or null (comparison not possible)
  • evidence_refs — per-side artifact references

Bundle

A self-contained result package: observations, features, pairs, runs. Stored per run. Reloaded for evidence display and counterfactuals.

ClusterRun

The clustering result: assignments (each material → cluster or singleton/noise), edges (accepted PairEvidence IDs), config, dataset_version, seed.

Assignment statuses: grouped | singleton | noise | insufficient_data.

Locators

ArtifactRef can optionally carry a Locator that pins the evidence to a specific position inside an artifact:

TypeFieldsUse case
text_spanstart, end (char offsets)Shared text in HTML body
image_rectx, y, width, height, frame_msMatched region in image / video frame

Analysis Pipeline

The core runner is src/methadata/runner/run.py :: run_experiment(). It is deterministic: same config + same observations → same run_id (SHA-256 of config + dataset_version + sorted canonical_ids).

# Simplified runner flow
obs = dedupe(observations)          # one canonical_id = one Observation
feats = extract_all(obs, extractors)
pairs = compare_all_pairs(obs, feats, comparators)
result = clusterer.cluster(obs, pairs, config)
# → {record: {...}, bundle: Bundle}
Deduplication: When multiple imports produce the same canonical_id, only one Observation participates in the run (chosen by smallest observation_id). Features are keyed by content, not observation — re-running with the same data is a no-op.

Two Operating Profiles

🧪 Demo / Baseline profile

Uses configs/baseline/baseline.json. Comparators: asset Jaccard only. Clustering: K01 connected components. Fast, no ML models required.

Summary message: "X materials share common images."

⚖️ Jury profile

Uses configs/demo/jury.json. Comparators: asset Jaccard + lexical TF-IDF + DOM structure. Clustering: K09 Fusion → K01 Components. Full evidence fusion with per-family ablation.

Summary message: "Campaign hypothesis based on narrative similarity and page template."

Atomic writes

All writes use tempfile.mkstemp + os.replace for crash-safety. A threading.RLock serialises mutations within one process. Blobs are content-addressed: writing the same file twice is idempotent.

Extractors

E01 — Asset Hash Extractor Working

Source: src/methadata/experiments/assets/adapters.py :: AssetHashExtractor

Produces two feature kinds:

  • asset/image_sha256 — one feature per creative_image or resource image/* artifact (SHA-256 string value).
  • asset/screenshot_sha256 — SHA-256 of the landing_screenshot (not used for grouping, tracking only).
An Observation with zero images produces an empty set. This is not a zero score — it means comparison is impossible (score=null).

E02 — Lexical Text Extractor Working

Source: src/methadata/experiments/lexical/text.py :: LexicalTextExtractor + adapters.py

Parses HTML/DOM and segments text into fields:

  • title — <title> and <h1>
  • body — main content text, stripped of nav/footer/script
  • cta — call-to-action elements (buttons, links with action verbs)
  • comments — user comments (tracked separately; can be merged)

Feature family/kind: lexical/text_field. Value is {field, text, refs} (the refs are ArtifactRef + TextSpan locators for excerpt display).

E03 — DOM Structure Extractor Working

Source: src/methadata/experiments/dom/adapters.py :: DomStructureExtractor

Reads landing_dom or landing_html (MHTML supported). Produces a normalised token sequence:

[depth, tag, open_start_offset, end_offset]
# text nodes replaced with synthetic '#t' token
# <head>, <script>, <style> excluded

Feature family/kind: dom_struct/dom_sequence. Value: {tokens, capture, chars}.

Perceptual Extractor (E09) Working

Source: src/methadata/experiments/perceptual/adapters.py :: PerceptualExtractor

For each image (creative_image or resource image/*):

  • pHash (perceptual/phash) — 64-bit perceptual hash, group classification: icon (max side ≤ threshold, skipped by comparators) or illustration.
  • Keypoints (perceptual/keypoints) — ORB descriptors for illustration images only. Contains pts (keypoint coords) and desc (binary descriptors).
Requires optional extras (extras=["perceptual"]). The extractor is listed as a supplemental extractor in Collection mode: SUPPLEMENTAL_EXTRACTORS = ("perceptual-extractor", ...).

Comparators

Asset Jaccard Working

Source: src/methadata/experiments/assets/adapters.py

Operates on the asset/image_sha256 feature set.

# Standard Jaccard
score = |A ∩ B| / |A ∪ B|

# Weighted Jaccard (corpus-aware)
score = Σ w(h) for h in A∩B / Σ w(h) for h in A∪B
        where w(h) = 1 / max(1, corpus_frequency[h])
Method IDRelationNotes
assets-jaccard-v1 shared_template Standard Jaccard — equal weight to all images
assets-weighted-jaccard-v1 shared_template Rare images count more; common images (logos, icons) discounted
When both sets are empty, or one side is empty, score=null. The explanation distinguishes these cases clearly.

Lexical TF-IDF Cosine Working

Source: src/methadata/experiments/lexical/adapters.py :: LexicalTfidfComparator

Compares text field-by-field using two analyzers (word n-grams and character n-grams) then combines with cosine similarity:

Default field weights: title=0.2, body=0.6, cta=0.2, comments=0.0

For each field (title, body, cta):
  word_score = cosine(TF-IDF word vectors)
  char_score = cosine(TF-IDF char-ngram vectors)
  field_score = average(word_score, char_score)

final_score = Σ (field_score × weight) / Σ weights_used
Method IDRelationNotes
lexical-tfidf-v1 shared_narrative Full title + body + CTA
lexical-tfidf-notitle-v1 shared_narrative Body + CTA only (title hidden)
IDF source: When no pre-fitted model is provided, IDF is computed from the current run's corpus. For the jury profile this is correct (full corpus available). For single-pair comparisons in FusionComparator, IDF is computed from just the two observations — this is noted in the explanation.

DOM Structure Comparators Working

Source: src/methadata/experiments/dom/adapters.py

All operate on the dom_struct/dom_sequence feature. Text content and identifiers are replaced by markers before comparison.

Method IDTechniqueRelation
dom-paths-jaccard-v1 Jaccard of tag-path sets (e.g. div>section>p) shared_template
dom-sequence-edit-v1 1 − Levenshtein(token_seq_A, token_seq_B) / max(|A|,|B|) shared_template
dom-sections-v1 Edit distance on structural landmark sequence (header, nav, main, h1–h3…) shared_template

Perceptual Comparators Working

Source: src/methadata/experiments/perceptual/adapters.py

Method IDTechniqueRelation
perceptual-phash-v1 Hamming distance between 64-bit pHashes; threshold-based score shared_template
perceptual-keypoints-v1 ORB keypoint matching across illustration images; score = ratio of matched keypoints shared_template
icon-group images (small logos/favicons) are excluded from both comparators to avoid false positives from common decorative elements.

Clustering

K01 — Connected Components (Threshold Graph) Working

Source: src/methadata/clustering/components/core.py

Method ID: components-threshold

Builds an undirected graph where an edge exists between two materials if their PairEvidence.score ≥ threshold. Groups are the connected components of this graph.

  • Deterministic regardless of observation order
  • When multiple PairEvidence for the same pair: picks highest score (tie-break: smallest evidence ID)
  • Assignment status: grouped (≥2), singleton (all comparisons below threshold), insufficient_data (all scores null)
# Config keys
{
  "threshold": 0.5,            # edge acceptance threshold (0, 1]
  "similarity_version": "...", # version fingerprint (invalidates cached results)
  "dataset_version": "...",    # corpus version fingerprint
  "relation": "shared_template",
  "method_id": null            # null = auto-detect single method
}

K09 — Evidence Fusion Working

Source: src/methadata/clustering/fusion/core.py :: fuse_and_cluster()

Method ID: fusion-v1

Relation: campaign_candidate

Fuses multiple independent evidence families into a single fused score per pair, then runs K01 on those fused scores.

Key Concepts

Similarity

Weighted average of available origin scores. Each family has a weight; families with the same origin are merged (count as one source).

Coverage

Σ weight of available comparisons / Σ weight of all configured families. Must be ≥ coverage_min (default 0.5) for a valid score.

Support

Number of distinct origins whose score ≥ support_min. Must be ≥ min_support (default 2). Without enough support, score is clipped below threshold.

Fusion Config Structure

{
  "threshold": 0.5,
  "coverage_min": 0.5,
  "min_support": 2,
  "similarity_version": "fusion-eval-v1(campaign)",
  "dataset_version": "...",
  "families": {
    "content-image": {
      "method_id": "assets-jaccard-v1",
      "weight": 1.0,
      "origin": "content-image",
      "support_min": 0.1
    },
    "content-text": {
      "method_id": "lexical-tfidf-v1",
      "weight": 0.8,
      "origin": "content-text",
      "support_min": 0.2
    },
    "dom-structure": {
      "method_id": "dom-paths-jaccard-v1",
      "weight": 0.8,
      "origin": "dom-structure",
      "support_min": 0.1
    }
  }
}

Fusion Outcomes per Pair

StatusConditionScore
ok Coverage OK + Support OK Weighted average [0, 1]
insufficient_coverage Too few families returned a score null
insufficient_support Not enough origins above support_min Clipped just below threshold (not null)
no_evidence No families returned any score null

Per-family Ablation

For every configured family, the fusion is re-run with that family disabled (ablation dict on FusionResult). This powers the scenario/counterfactual API endpoint.

Collection Mode

Source: backend/methadata_api/collection.py

Collection is a persistent SQLite-backed store of uploaded materials. It:

  • Accepts batch ZIP imports with multiple members
  • Deduplicates by content (canonical_id-based)
  • Runs the full fusion pipeline on the whole collection and publishes periodic snapshots
  • Exposes signals per material pair (top-24 by score)
  • Supports optional model-based extractors when METHADATA_COLLECTION_MODELS=1

Supplemental extractors (always available):

perceptual-extractor url-har-extractor extract-code (near-copy)

Model-gated extractors (METHADATA_COLLECTION_MODELS=1):

ocr-layout-extractor visual-embedding-extractor

Collection evidence fields (returned on GET /evidence/{id} for fusion-v1 in collection profile):

  • families — per-family name, score, and whether it supports the edge
  • signals — top supplemental signals for the pair
  • inactive_signals — labels of disabled method families

Scenario / Counterfactual API Jury only

Source: backend/methadata_api/scenarios.py :: RunScenarios

Endpoint: GET /api/v1/runs/{run_id}/evidence/{evidence_id}/scenarios?disabled=family_name

Given a completed jury run and a fusion-v1 evidence pair, re-runs the fusion with one or more evidence families disabled (counterfactual). Returns:

  • baseline — original run result for the pair + group membership
  • scenario — result with the specified families disabled
  • edge_changes — which pairs changed status (new edges, removed edges)
  • indirect_paths — shortest paths between pair members through the graph
  • minimal_masks — the smallest set of families whose removal breaks the connection
Results are computed on frozen evidence from the saved bundle. The graph is re-clustered but no new extraction/comparison is performed. LRU-cached per (run_id, observation_id) pair.

End-to-End Data Flow

# 1. INGEST
POST /api/v1/observations  (file or URL)
  → FileImporter.import_sources([path], store)
  → store.put_stream(fh)              # write blob under sha256
  → Observation + Artifact records    # written atomically as JSONL
  → returns ObservationCreated {observation_id, canonical_id, input_kind, artifacts[]}

# 2. QUEUE RUN
POST /api/v1/runs {observation_id, profile}
  → RunManager.create(oid, profile)   # saves state file, enqueues
  → returns {run_id, status: "queued"}

# 3. EXECUTE (background thread)
engine.compute_run(storage, run_id, observation_id, profile, progress)
  → selected = storage.for_profile(profile)   # demo or jury Storage
  → store = selected.store()
  → idx = selected.index()                    # {observation_ids, target_...}
  → wanted = idx.observation_ids + [observation_id]
  → observations = [store.observation(i) for i in wanted]
  
  if profile == "jury":
    → fusion_run(settings, observations, store, adapters, dataset_version, run_id)
       → collect_corpus_evidence(...)          # extract + compare all pairs
       → fuse_and_cluster(obs, raw, fusion_cfg)
       → rekey(bundle, run_id)
  else:  # demo / baseline
    → run_experiment(config, observations, adapters, reader=store)
       → extract features for each observation
       → compare all pairs (asset Jaccard)
       → cluster (K01 components)
  
  → build_view(run_id, bundle, labels, store, previews_dir, observation_id)
  → save run.json + bundle.json

# 4. POLL
GET /api/v1/runs/{run_id}
  → status: succeeded / running / queued / failed
  → on success: result = ClusterRunView {summary, materials[], clusters[], pair_evidence[]}

# 5. EXPLORE EVIDENCE
GET /api/v1/runs/{run_id}/evidence/{evidence_id}
  → build_evidence(run_id, bundle, view, evidence_id, store, previews_dir)
  → sides[0,1]: {material_id, label, items[{artifact, preview, text_excerpts}]}

# 6. COUNTERFACTUAL (jury only)
GET /api/v1/runs/{run_id}/evidence/{evidence_id}/scenarios?disabled=family_name
  → FamilySwitch.scenario(target, disabled)
  → compare_scenarios(inputs, baseline, scenario)
  → {baseline, scenario, edge_changes, indirect_paths, minimal_masks}
