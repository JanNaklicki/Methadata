# W01 · Kontrakt HTTP dla backendu i frontendu

Wykonaj kartę na branchu `codex/web-contract` od rewizji ze scalonymi zależnościami.

**Wymaga** — F01.  
**Odpowiadasz za** — contracts/http/openapi.yaml, contracts/http/examples/ i testy zgodności przykładów.

## Do wykonania

Zapisz kontrakt OpenAPI i przykłady żądań, odpowiedzi oraz błędów. Użyj rekordów F01 jako podstawy reprezentacji publicznych. Dokumentuj poniższe operacje:

| Operacja | Zachowanie |
|---|---|
| GET /api/v1/health | Gotowość API i magazynu, 200 lub 503. |
| POST /api/v1/observations | Przyjmij URL w JSON lub plik multipart, zwróć observation_id. Domyślnie URL podlega analizie offline. |
| GET /api/v1/demo | Podaj ID przygotowanej obserwacji do analizy oraz nazwę przykładowego zbioru. |
| POST /api/v1/runs | Przyjmij observation_id, zwróć 202 i run_id. |
| GET /api/v1/runs/{run_id} | Zwróć queued / running / succeeded / failed. Sukces zawiera publiczny widok ClusterRun, także przy niewystarczających dowodach. |
| GET /api/v1/runs/{run_id}/evidence/{evidence_id} | Zwróć opis dowodu obu stron i dostępne bezpieczne fragmenty tekstu lub referencje do statycznych podglądów. |

Podaj typy treści, błędy walidacji, zbyt duży plik, nieznane ID i błąd przebiegu. Ujednolić kod błędu i komunikat dla użytkownika. Przykłady powinny wystarczyć do napisania frontendu, gdy backend jest jeszcze w budowie.

## Odbiór

Walidator czyta specyfikację i sprawdza przykłady kompletnego wyniku, braku dowodów, oczekiwania oraz błędu. W publicznych odpowiedziach nie ma ścieżek systemu plików, aktywnego HTML ani surowych wartości sesyjnych. Podaj sposób sprawdzania zgodności przyszłej implementacji z kontraktem.
